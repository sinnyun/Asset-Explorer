# 文件夹分组资产视图设计

## 目标

恢复旧版按文件夹分组资产与分组折叠能力，同时保持 V2 的分页、虚拟渲染和大规模数据性能约束。

## 交互

- 普通工作区将当前已加载资产按 `folderId` 分组。
- 每个分组包含一个文件夹标题行和该组资产。
- 标题行显示文件夹名称、路径、当前已加载资产数量、折叠状态和文件夹上下文菜单。
- 点击标题右侧按钮切换折叠；折叠状态复用 `AssetState.collapsedGroupIds`。
- 文件夹没有加载到缓存时归入稳定的“未分类文件夹”组，不能静默丢失。
- 当前查询仍由资产分页接口控制，不为了分组读取全库资产。

## 技术方案

使用单一虚拟滚动容器，将可见内容扁平化为两类项目：`group-header` 和 `asset`。折叠组只生成标题项目，不生成该组资产项目。虚拟范围计算继续基于扁平项目数组，因此不会出现每个文件夹一个滚动容器，也不会在大量文件夹下创建大量 DOM 节点。

分组计算放在纯函数中，输入是当前分页资产、文件夹缓存和折叠 ID，输出稳定的虚拟项目数组。资产顺序沿用当前查询排序；文件夹组按文件夹路径和未分类组规则稳定排序。

## 边界与性能

- 单页最多处理后端允许的 300 个资产摘要。
- 每个分组标题只显示当前页已加载资产数量，避免把局部统计误认为全库统计。
- 虚拟列表只渲染视口加 overscan 范围。
- 折叠/展开只改变扁平项目数组，不触发资产重新查询。

## 验收标准

1. 同一 `folderId` 的资产出现在同一个分组中。
2. 折叠组仍显示标题，且该组资产不在虚拟项目中。
3. 展开后恢复该组资产，其他组折叠状态不改变。
4. 未知文件夹资产显示在未分类组。
5. 网格和列表模式均使用同一分组模型。
6. 前端和 Rust 既有测试全部通过。
