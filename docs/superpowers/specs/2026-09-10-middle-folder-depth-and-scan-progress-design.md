# 中间文件夹层级控制与索引进度设计

## 目标

为深层项目目录提供更清晰的中间文件夹卡片视图，并让索引过程显示可理解的数字进度。功能只改变中间区域的展示，不改变左侧文件树、数据库、文件监控和项目内部资产展开逻辑。

## 已确认的交互规则

顶部栏提供固定数字层级控制：`1 2 3 4 5 6 7 8 ∞`。

- `1` 到 `8` 表示从当前工作区根目录开始允许显示的最大相对文件夹深度。
- `∞` 表示显示所有已加载层级。
- 默认值为 `3`，适配“主目录 → 分类目录 → 项目目录”的常见结构。
- 控制器只作用于中间文件夹卡片区域。
- 左侧文件夹树继续使用现有的独立展开状态，不受数字层级控制影响。
- 用户进入某个文件夹后，中间区域切换为该文件夹上下文；此时层级从当前文件夹重新计算，项目内部文件夹和资产仍可按现有方式完整查看。
- 层级控制是纯 UI 状态，不写入数据库，不影响监控、扫描、资产查询或文件夹树缓存。

## 方案

### 中间文件夹卡片

在 `MainArea` 顶部工具栏增加一个紧凑的数字选择器。`App` 保存 `folderCardDepth` 状态，并将其传入 `MainArea`。中间文件夹列表根据当前查询上下文和文件夹 `parentId` 关系计算相对深度，仅保留深度不超过所选值的卡片。

过滤只作用于 `filteredFolders` 的展示副本，不改变 `folderResults` 的分页数据，也不改变 `state.folders`。因此用户切换层级不会触发数据库查询或扫描。

当当前选中的文件夹发生变化时，深度计算根节点同步变化；当进入项目目录后，项目内部层级重新从 1 开始。资产查询仍使用现有的 `activeFolderId` 与 `includeSubfolders` 规则。

### 索引进度

现有事件流保留边扫描边显示的行为，但补充紧凑进度字段：

- `scan:started`：路径、根目录名称、阶段、总数（若遍历阶段尚未完成则为 0）。
- `scan:progress`：已处理数量、总数、阶段、每秒处理量和可选预计剩余时间。
- `scan:finished`：最终数量、耗时和完成状态。
- `scan:failed`：错误信息和失败状态。

前端 `ScanProgress` 增加阶段、速度和预计剩余时间字段。底部进度条显示“已处理 / 总量、百分比、速度、阶段”，总量未知时显示“正在统计文件数量”，扫描过程不阻塞资产列表。

索引阶段使用固定代码映射到中文显示：`discovering`（扫描目录）、`indexing`（读取文件）、`persisting`（写入索引）、`finished`（已完成）。事件字段保持小而稳定，不发送资产快照。

## 错误处理

- 层级值始终限制为 `1..=8` 或 `Infinity`，非法值回退到 `3`。
- 目录关系缺失或循环时，卡片保守地视为当前上下文的直接项，不能导致页面崩溃。
- 总量为 0 或速度不可计算时不显示错误的百分比/预计时间。
- 扫描失败保留最后的已处理数量并显示错误，不清空已经建立的资产。
- 前端收到旧格式事件时使用现有字段默认值，保证开发服务器和桌面事件流兼容。

## 测试范围

- 文件夹层级计算：根目录、三层项目结构、切换当前文件夹、缺失父节点和循环保护。
- 中间卡片过滤只影响显示数组，不改变左侧文件树数据。
- 数字控制器的默认值、1 到 8、∞ 和非法输入回退。
- 索引进度事件字段映射、未知总量、速度/预计时间边界、完成和失败状态。
- TypeScript 类型检查、前端回归测试、Rust 扫描事件测试和生产构建。
